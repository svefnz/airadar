# deployment

## Purpose

定义 AI Free Radar 的构建、校验与发布行为：GitHub Pages 部署（含子路径与自定义域名支持）、CI 失败保护、最小权限，以及适用于私有仓库的替代部署通道。

## Requirements

### Requirement: GitHub Pages 部署与子路径 base

站点必须可部署到 GitHub Pages，并正确支持三种形态：用户主页域名、项目子路径、自定义域名。部署在子路径（如 `/airadar/`）时，页面所有内部导航与资源引用必须保留该前缀；点击跳转不得丢失前缀导致 404。

#### Scenario: 子路径跳转正常

- **WHEN** 站点部署在 `/airadar/` 子路径下且用户点击任意内部链接
- **THEN** 目标 URL 包含 `/airadar/` 前缀并可正常访问

#### Scenario: 根路径部署正常

- **WHEN** 站点部署在根路径（用户主页或自定义域名）
- **THEN** 内部导航使用根路径且不产生多余前缀

### Requirement: 构建与发布自动触发

代码提交或数据文件提交都必须触发自动化流水线：安装依赖、类型检查、数据 Schema 与业务校验、重复检测、单元测试、静态构建，随后发布。

#### Scenario: 数据提交触发重建

- **WHEN** 自动化任务只修改 `data/radar.json` 并提交
- **THEN** 流水线自动运行校验、构建并发布最新数据

### Requirement: 失败保护

当数据校验失败或构建失败时：必须阻止错误版本发布；保留上一版可用站点；给出明确的流水线错误信息；不得自动删除任何历史数据。

#### Scenario: 坏数据不发布

- **WHEN** 数据文件不符合 Schema 或业务约束
- **THEN** 发布流程中止，上一版站点继续可访问

#### Scenario: 消息数据不受删除

- **WHEN** 校验或构建失败
- **THEN** 系统不自动修改或删除数据历史

### Requirement: 最小权限

部署流水线必须使用最小权限：仅授予执行流水线所必需的权限（如内容只读、Pages 写与 OIDC token），不得授予无关注权限。

#### Scenario: 流水线权限受限

- **WHEN** 流水线运行
- **THEN** 其权限仅为执行构建与发布所需的最小集合

### Requirement: 替代部署通道

当仓库为私有（免费计划不支持 GitHub Pages）或用户选择其他托管时，系统必须支持无代码改动的替代部署：静态构建产物可被 Cloudflare Pages 等平台直接部署，且要求构建环境满足运行时版本约束（如 Node 22+）。

#### Scenario: 私有仓库部署到 Cloudflare

- **WHEN** 私有仓库通过 Cloudflare Pages 部署
- **THEN** 使用同一构建命令产出 `dist` 目录部署，站点可访问且无需改动产品代码

### Requirement: 自定义域名

支持通过托管平台配置自定义域名，解析后站点可通过自定义域名访问，所有资源与导航仍正常。

#### Scenario: 自定义域名生效

- **WHEN** 为站点配置自定义域名及其 DNS 记录
- **THEN** 通过自定义域名访问站点，页面资源与导航完整可用
