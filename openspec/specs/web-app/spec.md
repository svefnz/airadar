# web-app

## Purpose

定义 AI Free Radar 网页应用的行为契约：页面集、数据呈现、搜索筛选排序、URL 状态、图表、主题与移动端适配，并保证所有呈现均来自真实数据且对不可信数据安全处理。

## Requirements

### Requirement: 页面集

站点必须提供以下页面：总览 Dashboard、资源库、平台详情（每平台独立页）、新平台发现、变更记录、监控状态。平台详情页必须展示平台基础信息、免费权益、历史变更与证据来源。

#### Scenario: 访问全部核心页面

- **WHEN** 用户导航到任意核心页面
- **THEN** 页面正常渲染，且各页间链接可用，不出现资源加载失败

### Requirement: Dashboard 指标真实性

Dashboard 顶部指标必须由真实数据计算：当前有效免费资源数、最近 24 小时/7 天新发现数、即将过期活动数、原生 API 与客户端资源数、最近一次成功监控时间。必须区分“最后尝试执行时间”与“最后成功完成时间”；不得将尝试执行冒充成功完成。数据过期或监控异常时必须给出可见提示。

#### Scenario: 失败运行不显示成功时间

- **WHEN** 最近一次监控运行失败
- **THEN** Dashboard 不显示为成功完成，并呈现异常状态提示

#### Scenario: 无数据时显示空态

- **WHEN** 没有可用资源数据
- **THEN** Dashboard 显示合理空状态，不伪造示例统计

### Requirement: 搜索筛选排序与 URL 同步

资源库必须支持按平台名、模型名、活动名、资源描述与域名搜索；支持多条件组合筛选（接入方式、额度周期、状态、可信度、绑卡/实名、接口兼容、上下文、Tool Calling、即将过期、长期免费等）；支持多种排序（最近发现、最近更新、即将过期、额度价值、平台名、最近核验）。筛选条件必须同步到 URL，刷新或分享后可保留。额度价值排序不得跨单位比较。

#### Scenario: 筛选同步 URL

- **WHEN** 用户设置筛选条件
- **THEN** URL 反映筛选状态，刷新页面后筛选保持

#### Scenario: 组合筛选生效

- **WHEN** 用户同时选择多个筛选器
- **THEN** 结果只包含同时满足全部条件的活动

### Requirement: 视图切换

资源库必须支持卡片视图与紧凑列表视图切换，切换不丢失当前筛选与排序状态。

#### Scenario: 视图切换保留状态

- **WHEN** 用户切换视图
- **THEN** 筛选与排序结果保持不变，仅呈现方式变化

### Requirement: 平台详情与未确认呈现

平台详情页必须将同一平台的多个独立权益分别展示，不得合并为一条；每个权益展示模型与额度、领取方式、恢复周期、有效期、截止日期、速率限制、绑卡/实名/地区限制、API 或客户端支持、隐私风险与官方证据链接。任何无法确认的字段必须显示“未确认”。

#### Scenario: 多权益独立展示

- **WHEN** 平台存在注册赠额与每日免费两个权益
- **THEN** 详情页分开展示两项权益及其各自字段

### Requirement: 图表使用真实数据

Dashboard 图表（30 天新增趋势、API/客户端占比、额度恢复周期分布、状态分布）必须基于真实资源数据渲染；无数据时显示空状态，禁止伪造示例统计。

#### Scenario: 图表空态

- **WHEN** 某类数据为空
- **THEN** 对应图表显示空状态而非编造数值

### Requirement: 主题切换

站点必须支持浅色、深色与跟随系统三种主题，主题偏好本地持久化，并在页面加载早期应用以避免闪烁。

#### Scenario: 偏好持久化

- **WHEN** 用户选择深色主题并刷新页面
- **THEN** 页面仍保持深色主题

### Requirement: 移动端适配

站点必须在 iPhone Safari 等移动浏览器可正常使用：导航可达、筛选易操作、资源卡片合理压缩、详情内容无横向溢出；移动端搜索、筛选、阅读详情与打开外部领取链接均可用。

#### Scenario: 移动端无横向溢出

- **WHEN** 在移动视口打开资源库与详情页
- **THEN** 页面不出现横向滚动溢出

### Requirement: 前端安全

页面不得暴露任何私密 Token；不得执行来自数据文件的任意 HTML/JavaScript（数据一律按文本渲染）；外部链接必须校验并规范化 URL，且带 `rel="noopener noreferrer"`；加载 GitHub 数据时必须进行 Schema 校验，错误数据不得导致整页崩溃。

#### Scenario: 恶意数据不执行

- **WHEN** 数据文件含脚本或非法 HTML 文本
- **THEN** 页面仅将其作为纯文本展示，不执行

#### Scenario: 非法数据页面兜底

- **WHEN** 数据无法通过 Schema 校验
- **THEN** 页面显示错误状态而非白屏或崩溃
