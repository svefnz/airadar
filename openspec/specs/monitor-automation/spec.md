# monitor-automation

## Purpose

定义 ChatGPT 自动化监控任务的运行合同：每 3 小时执行免费额度与新平台搜索，经核验与去重后增量写入 GitHub 数据文件，并如实记录每次运行结果，支撑监控状态页面与通知策略。

## Requirements

### Requirement: 调度频率与搜索范围

监控任务必须按 3 小时间隔执行，并独立完成两类搜索：A 类免费额度活动搜索（注册赠额、公测限免、签到奖励、每日/每周/每月额度、长期免费 API、客户端积分、模型首发、额度变化、活动延期/结束等）；B 类新平台主动发现，范围覆盖最近 48 小时、7 天、30 天以及历史仍有效的免费活动。B 类必须主动调查 Product Hunt、Hacker News、GitHub、Hugging Face、Reddit、Linux.do、V2EX、X 等渠道，禁止仅搜索已知平台。

#### Scenario: A 类搜索完成

- **WHEN** 监控任务完成 A 类搜索
- **THEN** 运行记录中 `searchACompleted` 为真，且至少覆盖官方定价/活动页与主渠道

#### Scenario: B 类主动发现

- **WHEN** 监控任务执行 B 类搜索
- **THEN** 运行记录中 `searchBCompleted` 为真，且搜索内容包含独立的新平台发现，而不限于已知平台

### Requirement: 多语言与排除规则

搜索必须覆盖中文、英文、日文等多种语言来源。仅可于官方客户端使用的福利不得被排除；但客户端赠额不得被描述为开放 API。不得因为“只能客户端用”而忽略福利。

#### Scenario: 客户端专属福利入库

- **WHEN** 发现仅限官方客户端的免费额度
- **THEN** 记录为接入方式“客户端专用”，其描述不得声称属于开放 API

### Requirement: 官方核验与来源分级

每项活动必须保留证据来源，并区分类型：官方来源（定价页、活动页、文档、公告、官方 GitHub）与社区来源（社区实测、讨论）。社区推测不得标记为官方承诺；无法确认的信息必须标记为“待核实”或“未确认”。已标记官方确认的活动，必须能够追溯到官方证据链接。

#### Scenario: 社区来源不被升级

- **WHEN** 仅存在社区讨论来源
- **THEN** 活动核验状态不得为“官方确认”，来源类型保持“社区”

### Requirement: 增量写入与提交后验证

自动化任务只能更新被明确允许的数据文件（`data/radar.json` 及待导入目录），不得修改网页源代码。写入前必须读取并校验现有数据与 schemaVersion；生成更新后的完整数据全文自检后，通过 GitHub 连接器提交。提交后必须重新读取目标文件并比对内容，验证写入确实成功。

#### Scenario: 写入后回读验证

- **WHEN** 自动化成功提交数据文件
- **THEN** 重新读取文件并确认包含本次变更，再记录为成功

#### Scenario: 越权修改被禁止

- **WHEN** 自动化尝试修改网页源码或其他非数据文件
- **THEN** 该写入被拒绝，任务不得执行

### Requirement: 运行记录真实性

每次监控必须追加运行记录，包含开始/完成时间、状态、A/B 完成标志、检查来源数、候选数、新增/更新/过期数、失败项与提交哈希。状态必须是真实结果：标记成功必须同时完成 A/B 搜索并具有完成时间；任何一步失败都不得标记成功。页面必须展示真实运行记录，失败或异常时显示异常状态，不得永久显示“运行正常”。

#### Scenario: 失败运行如实记录

- **WHEN** B 类搜索超时或失败
- **THEN** 运行状态为失败或部分完成，页面呈现异常且不显示成功

#### Scenario: 成功运行推进同步时间

- **WHEN** 运行成功且写入完成
- **THEN** 系统将成功同步时间更新为该运行的真实完成时间

### Requirement: 审批与冲突处理

若 GitHub 写入需要人工审批，任务必须保留待审批状态并如实报告，不得声明写入成功；同时应提供可验证的替代产物（如待导入 JSON 补丁）。遇到文件版本冲突时必须重新读取最新数据并重新合并，禁止强制覆盖。前端、仓库与提示词中不得存放私人 Access Token 以绕过审批。

#### Scenario: 写入待审批

- **WHEN** GitHub 连接器要求人工审批
- **THEN** 任务报告“待审批”，生成待导入补丁文件，且本次运行不得记为成功

#### Scenario: 并发冲突重试

- **WHEN** 提交时文件已被其他写入修改
- **THEN** 重新读取最新版本、重新合并后再次提交

### Requirement: 无新增活动时的行为

监控未发现新增免费福利时，仍必须记录实际执行结果（A/B 是否完成），更新监控状态页面；无需给用户发送例行消息，也不得伪造新增资源。

#### Scenario: 空结果仍记录运行

- **WHEN** A/B 搜索完成但无新福利
- **THEN** 运行记录被追加且 A/B 完成标志为真，页面更新时间刷新，但无新增资源

### Requirement: 通知策略

仅在以下情况通知用户：新平台提供高价值赠额、新发现大量免费 Tokens、高质量 Coding 模型限时免费、即将结束的重要活动、已知平台重大额度变化、监控系统持续失败。常规检查成功、无变化、旧活动重新核验等不得主动通知。

#### Scenario: 例行检查不通知

- **WHEN** 监控成功且无变化
- **THEN** 不发送通知消息

#### Scenario: 重要新福利通知

- **WHEN** 发现高价值新平台赠额
- **THEN** 向用户发送通知
