# Spec Delta

## Purpose

定义用户个人管理能力：收藏、领取状态、忽略、备注等个人数据仅保存在当前浏览器 localStorage 中，按稳定活动 ID 关联，绝不污染公共资源数据，并支持导出、导入与清除。

## ADDED Requirements

### Requirement: 个人数据仅存本浏览器

个人状态（收藏、领取状态、忽略、备注等）必须仅在当前浏览器 localStorage 中保存，不得写入公共数据文件或任何远端服务。页面必须向用户明确提示该数据的浏览器本地属性与不跨设备同步限制。

#### Scenario: 刷新后状态保留

- **WHEN** 用户标记收藏或已领取并刷新页面
- **THEN** 个人状态仍保留

#### Scenario: 公共数据不受污染

- **WHEN** 用户产生任意个人状态变更
- **THEN** 公共资源数据文件不变，其他用户不受影响

### Requirement: 活动个人状态

每项活动必须支持以下个人标记：未领取（默认）、已领取、已过期、不感兴趣；额外支持收藏、个人备注与领取日期记录。用户可按领取状态筛选资源列表。

#### Scenario: 标记已领取

- **WHEN** 用户将活动标记为已领取
- **THEN** 该活动在个人情境中显示为已领取，并记录领取日期

#### Scenario: 忽略与取消

- **WHEN** 用户将活动标记为不感兴趣或取消该标记
- **THEN** 对应状态即时更新，可随时变更

### Requirement: 稳定 ID 关联

个人状态必须通过活动稳定 ID 关联，活动 ID 变化（数据更新）不得打乱个人记录空间。

#### Scenario: 数据更新后个人记录仍在

- **WHEN** 活动额度或截止日期变化（ID 保持稳定）
- **THEN** 该活动的个人状态继续关联并可用

### Requirement: 导入导出与清除

必须提供个人记录导出（JSON）、导入与清除功能；导入时必须做版本兼容处理，失败或版本过新时给出明确错误，且不损坏现有数据。

#### Scenario: 导出导入往返

- **WHEN** 用户导出个人记录后在另一浏览器导入
- **THEN** 个人状态被恢复，公共数据不受影响

#### Scenario: 非法导入拒绝

- **WHEN** 导入文件不是合法 JSON 或版本过新
- **THEN** 系统拒绝导入并提示原因，现有个人数据保持

### Requirement: 个人数据版本迁移

个人数据必须带版本标识；读取时自动迁移可兼容的旧版本，遇到未知未来版本时拒绝读取（避免损坏）并给出提示。

#### Scenario: 旧版本自动迁移

- **WHEN** 本地个人数据为已支持的历史版本
- **THEN** 读取时自动迁移到当前结构

#### Scenario: 未来版本拒绝

- **WHEN** 本地个人数据版本高于当前支持的版本
- **THEN** 系统拒绝读取并提示版本过新，不覆盖原数据
